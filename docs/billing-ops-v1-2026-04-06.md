## 1. 购买成功 / 失败反馈策略

### 已实现

| 场景 | 反馈方式 | 内容 |
|------|----------|------|
| 订阅支付成功 | QR Modal 成功态 + Toast | 显示套餐名、到账订阅积分数、每日体验赠额 |
| 通用积分包支付成功 | QR Modal 成功态 + Toast | 显示到账通用积分数（含赠送明细） |
| 支付失败/超时 | QR Modal 失败态 + Toast | 显示具体商品名 + "未完成支付，请重试" |
| 取消支付 | 关闭 QR Modal | 无额外提示 |

### 流程

1. 用户点击订阅/购买 → 前端 POST `/api/billing/create-order` → 创建 Order（pending）
2. 返回微信支付二维码 → 前端 QRModal 展示 + 开始轮询
3. 用户扫码支付 → 微信 webhook → 后端验签 + 幂等写入 → Order 状态 → paid
4. 前端轮询 `/api/billing/order/:id` → 检测到 paid → QRModal 成功态（展示商品信息）
5. 1 秒后自动关闭 + Toast 提示 + 刷新用户状态

### 积分到账对应关系

| 商品类型 | 到账字段 |
|----------|----------|
| 订阅（basic/pro/team） | `subscriptionCredits` += 对应额度, `plan` 更新, `expireAt` 延长 |
| 通用积分包 | `generalCredits` += 对应额度 |

## 3. 升级订阅规则

> **状态：规则说明，未实现自动化**

### 规则

1. **即时生效**：用户购买更高级套餐后，新套餐立即生效
2. **积分叠加**：新套餐的订阅积分立即全额发放，不按剩余天数折算
3. **旧套餐积分**：已发放的订阅积分不回收，本月内可继续使用
4. **到期时间**：从购买日起算 30 天，覆盖旧到期时间
5. **每日体验赠额**：按新套餐标准发放（例 Basic 60/日 → Pro 120/日）

### 当前实现

- 用户可以直接在 `/billing` 购买更高级套餐
- webhook 收到支付后：更新 plan、叠加 subscriptionCredits、延长 expireAt
- **未实现**：旧套餐剩余天数折算退款或抵扣

## 4. 降级订阅规则

> **状态：规则说明，未实现自动化**

### 规则

1. **到期后生效**：降级不立即执行，当前套餐有效期内继续享受原权益
2. **到期后自动降级**：`getOrCreateUser()` 检测 `expireAt < now` 时自动将 plan 改为 free
3. **订阅积分不回收**：已发放的订阅积分在有效期内可继续使用
4. **通用积分不受影响**：通用积分始终有效
5. **每日体验赠额**：降级后按新套餐标准发放

### 当前实现

- 订阅到期自动降至 free（已实现，`getOrCreateUser` 中）
- **未实现**：用户主动降级的前端入口和流程
- **未实现**：到期前提醒

## 5. 取消订阅规则

> **状态：规则说明，未实现自动化**

### 规则

1. **到期后生效**：取消订阅 = 不续费，当前周期内权益不变
2. **到期后降为 Free**：与降级逻辑一致
3. **已发放积分不回收**：
   - 订阅积分：有效期内可用，到期后不再发放
   - 通用积分：不受影响
   - 新人赠送：不受影响
   - 奖励积分：不受影响
4. **每日体验赠额**：恢复为 Free 标准（120/日）

### 当前实现

- 自动到期降级已实现
- **未实现**：取消订阅的前端入口
- **未实现**：取消确认弹窗

## 6. 通用积分与订阅中断的关系

### 规则

1. **通用积分不受订阅状态影响**：购买的通用积分始终可用
2. **订阅中断后**，积分消耗仍按五级优先级：
   - 每日体验赠额 → 新人赠送 → 订阅积分（若有剩余）→ 通用积分 → 奖励积分
3. **订阅积分月末清零**（规则已确认，自动清零逻辑未实现）
4. **通用积分无有效期**：只要账户存在，通用积分持续可用

### 当前实现

- 五级消耗顺序已实现
- **未实现**：订阅积分月度自动清零

## 7. Team 席位变更规则

> **状态：规则说明，未实现自动化**

### 规则

1. **按人计费**：Team 套餐 ¥199/人/月
2. **每位成员独立积分**：
   - 6,000 订阅积分/人/月
   - 120 每日体验赠额/人/日
3. **增加成员**：
   - 新成员加入后，按剩余天数折算首月费用（规则未实现）
   - 新成员获得完整的每月订阅积分
4. **移除成员**：
   - 成员被移除后，其剩余订阅积分不转移
   - 已分配的奖励积分不回收
5. **老板/管理员权限**：
   - 可发放奖励积分给成员
   - 可查看成员积分使用情况（未实现）
   - 可管理成员列表
6. **奖励积分规则**：
   - 由老板/管理员发放
   - 成员可用于任务执行
   - 不可转赠、不可折现（当前阶段）
   - 未来可能支持 8 折折现

### 当前实现

- Team 套餐购买已可用
- 工作区邀请/成员管理已实现
- **未实现**：按成员数计费的支付流程
- **未实现**：成员增减时的积分和费用调整
- **未实现**：奖励积分发放接口
- **未实现**：管理员积分查看面板
